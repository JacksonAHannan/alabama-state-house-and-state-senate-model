How to save progress and hand off to an implementer agent

This HTML file is the internal source of truth. It is not a public-site asset, a warehouse output or a publication approval.

  1. Check or uncheck an item and add evidence under “Evidence / disposition.” Counts and history update immediately. Browser drafts are saved locally when storage is available.
  2. Select Download updated HTML. Review the downloaded file, then replace project_docs/PROJECT_COMPLETION_CHECKLIST.html in the repository with that file. Downloads do not automatically modify repository files; browser storage does not sync between people or devices.
  3. An agent can instead edit the embedded checklist-data JSON directly: update the task's done and evidence, append a UTC history snapshot with at, done, total and event, and change revision to a new unique value. Retain stable task IDs and all prior history. Counts are derived, not manually maintained.
  4. When changing scope, preserve earlier snapshots and their original totals. Document added/removed tasks in a new history event. Keep deferred research visible with rationale rather than silently deleting a difficult requirement.
  5. Merge concurrent repository edits by task ID and review history conflicts. This is a single-editor file, not a collaborative server; coordinate ownership before editing.

Phase 1 sets the contract; Phase 2 repairs shared dependencies. Product Phases 3–6 may proceed in parallel once their inputs are ready. Phase 7 verifies the integrated release. The research-v4 and optional-finance items require a decision, not mandatory expansion.
