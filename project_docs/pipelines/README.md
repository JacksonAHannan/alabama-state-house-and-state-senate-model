# Component pipeline references

These documents describe individual source, compatibility, or evidence stages.
They are not a second set of canonical product entry points. Start with
[Canonical pipelines](../CANONICAL_PIPELINES.md) and the
[data contracts](../DATA_CONTRACTS.md), then read only the relevant component.

Counts, provider availability, acquisition gaps and command outputs describe
the recorded input/run. Verify present manifests and source-repair dependencies
before treating them as current. An official-only interface can have gaps even
when the broader canonical history contains another validated provider.

Ingestion, identity review, evidence processing, research analysis and publication
are separate operations. Do not execute every command in a reference document
to render a page or restart acquisition merely because an old gap is listed.
Optional finance and polling-transfer references are not mandatory inputs to
every product.

The [documentation audit](../audits/DOCUMENTATION_ARCHITECTURE_AUDIT_2026_09_05.md)
records retained snapshots, current routing, and remaining implementation issues.
